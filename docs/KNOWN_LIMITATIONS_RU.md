## Реализованные механизмы

1. **Обнаружение магазинов** — три источника с дедупликацией по ссылке на объект:
   `placeableSystem.placeables` → `mapHotspots` (SHOP) → `ShopTrigger`.
   `storeSpawnPlaces` **не** используется как источник (это точки появления покупок).
   Исключаются `spec_sellingStation`, `spec_animalDealer`, собственные мастерские.
   `spec_buyingStation`/`getBuyingStation` НЕ считаются магазинами покупки — это станции
   продажи/приёмки (`BuyingStation` наследует `LoadingStation`).
   `canOpenInterface` выставляется только после проверки реального интерфейса (`getStoreOpenMode`).
2. **Машина состояний заказа** (`ORDER_STATE`): IDLE, SHOP_SELECTED, FULFILLMENT_SELECTED,
   SHOP_OPENING, SHOP_OPEN, PURCHASE_PENDING, PURCHASE_CONFIRMED, DELIVERY_PENDING,
   DELIVERY_COMPLETED, DELIVERY_FAILED, CANCELLED, COMPLETED.
3. **Подтверждение покупки** — реальное создание объекта через хуки
   `VehicleLoadingData.load` / `PlaceableLoadingData.load`, привязанные к `orderToken`.
   Финансовые события (`FarmStats.changeFinanceStats`) используются только для расчёта
   платы за доставку и фильтруются по `PURCHASE_STAT_TYPES`.
4. **Завершение заказа** — успех возможен только когда завершены ВСЕ загрузки заказа
   (`pendingLoadCount == 0`); при зависших загрузках срабатывает страховочный таймаут 15 с,
   и заказ закрывается как ошибочный — успех не заявляется.
5. **Восстановление мест спавна** — снимок ВСЕХ полей места (`snapshotPlace`), сравнение через
   `snapshotsEqual`; идемпотентно; при конфликте с чужими изменениями восстановление
   пропускается с предупреждением в лог (`lastRestoreConflict = true`, возврат `false`).
6. **Валидация места доставки** — 9 точек габарита, перепад высот, уклон, вода,
   `overlapBox`-коллизии, отступ от игрока/машины; FAIL-SAFE при недоступности API.
7. **Паллеты** — размещаются линией вдоль перпендикуляра к направлению доставки с шагом
   «ширина палеты + 1 м»; используются габариты из данных станции.
8. **Финансы** — комиссия 2,5 % (макс. 5000) списывается при успешном завершении;
   результат проверяется по фактическому изменению баланса фермы (`withChargeVerification`);
   если баланс не изменился сразу, проверка откладывается на ~1 с (`chargeVerifyPending`),
   чтобы не создавать ложный долг при асинхронном обновлении денег.
   Неудачное списание сохраняется в `unpaidFee` и погашается следующим успешным заказом.
   Плата за звонок — 10, списывается при нажатии «Позвонить».
   При выгрузке карты комиссия не списывается, а сохраняется долгом.
9. **Открытие магазина** — только интерфейс выбранной точки; общего fallback на `ShopMenu`
   нет: если открыть не удалось, плата за звонок возвращается (`refundCallFee`),
   заказ отменяется (`FSP_STORE_OPEN_FAILED`). Закрытие каталога учитывается только
   для каталога, открытого модом (`catalogOpenedByUs`).
10. **Интерфейс** — состояния normal/hover/pressed/selected/disabled/focused,
    фокус по TAB, активация по Enter, ESC/Backspace, блокировка управления игроком.
11. **Логирование** — префиксы `[FarmShopPhone][ShopDiscovery|UI|Input|Order|Purchase|Delivery|SpawnRestore]`.

## Известные ограничения и риски

1. **Ассортимент не привязан к магазину.** Открывается стандартный каталог FS25;
   мод не фильтрует товары по выбранной точке.
2. **Проверка каждой палеты по отдельности не реализована.** Валидируется центральная
   точка доставки; крайние позиции линии могут попасть на препятствие/склон.
   Это этап B аудита v0.2.5.1 — в работе.
3. **`PlaceableLoadingData`: фактический путь вызова callback не подтверждён исходниками**
   (`self:loadPlaceable` в Lua не определён). Обработчик толерантный; при зависшей загрузке
   срабатывает таймаут ожидания (см. п. 4 «Реализованных механизмов»).
4. **Плата за звонок** списывается при каждом нажатии «Позвонить», включая случаи,
   когда игрок просто открыл каталог и вышел без покупки. Если магазин открыть не удалось —
   плата возвращается.
5. **Долг по комиссии** хранится в памяти (`unpaidFee`), а не в сохранении игры;
   при выгрузке без погашения он может быть утерян.
6. **Мультиплеер** отключён (`supported="false"`).
7. **Конфликт мест спавна**: если другой мод изменит те же места спавна, восстановление
   пропускается (не затирает чужие данные) — точка может остаться изменённой.
8. **Загрузка текстур**: `loadUiAssets()` не повторяет попытку, если `uiAssets` уже создан;
   частично незагруженный набор не догружается.

## Обязательные игровые проверки (не выполнены)

1. Открыть/закрыть телефон без заказа; проверить ESC и O.
2. Выбор магазина и возврат; TAB/Shift+TAB и Enter.
3. Самовывоз: покупка недорогого товара, товар в штатном месте.
4. Доставка: одна палета / три палеты — нет наложения объектов.
5. Частичная ошибка размещения: успех НЕ показывается, товар не теряется.
6. Полный отказ размещения: понятная ошибка, плата не списывается.
7. Посторонний `PalletSpawner` / загрузка во время активного заказа — состояние не меняется.
8. Ошибка списания комиссии → повторное погашение при следующем заказе.
9. Каталог закрыт без покупки — уведомления об успехе нет, плата не списана.
10. Загрузка/выгрузка карты во время открытого каталога; повторное открытие телефона после ошибки.
11. Покупка крупной техники.
12. Несколько карт и пользовательские торговые точки.

**Признак готовности:** прохождение сценариев в FS25 и отсутствие новых Lua/XML ошибок в `log.txt`.
